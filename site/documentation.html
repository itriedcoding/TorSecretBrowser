Getting started

Download the installer for your platform from the downloads page and install it. The app carries its own copy of Tor, so there is no separate Tor installation step.

  1. Install and launch the application.
  2. On first run it starts the bundled tor daemon and shows live bootstrap progress on the status overlay.
  3. When it reaches 100%, you are connected. Type any address in the toolbar — including .onion services.
Bootstrapping can take from a few seconds to a minute depending on your network and the current Tor consensus.

Using the browser

  • Address bar: accepts normal URLs, domains and .onion addresses. A full https:// URL is used as-is; a bare host like example.com or a .onion name is opened over http://, so type https:// yourself when a site requires it.
  • Tabs: each tab is an isolated session with its own circuit credentials. Open as many as you like.
  • Tor status chip: shows bootstrap progress; click it to expand the diagnostic log and see the daemon's output.
  • New Identity: rotates your circuits and clears all per-tab state in one action.

Automatic updates

Installed builds keep themselves current. Shortly after Tor reaches 100%, the app makes one anonymous request — through the very same Tor connection — to the project's GitHub releases to find out whether a newer version exists. Nothing is sent except that version request, and you are always asked before anything is downloaded or installed.

  • Routed through Tor. Version checks and update downloads use the app's Tor SOCKS proxy, never the clearnet, so they are indistinguishable from your normal browsing.
  • Windows & Linux. The update downloads in the background; when it is ready, choose Restart & install and the app relaunches on the new version.
  • macOS. Auto-install requires a code-signed build. These builds are unsigned, so the app detects a new version and opens the download page for you instead of pretending to install it.
  • Manual check. Click the ↓ button in the toolbar at any time to check, read the release notes and install.

Every release also publishes its update metadata (latest*.yml) and a SHA256SUMS.txt so each downloaded file can be independently verified — the same values the file scanner checks against.

Clearnet & .onion link directory

The new-tab page ships with a built-in directory of clearnet and .onion addresses for Tor Project services and a few well-known sites. The Open a link box at the top of that page, and the toolbar address bar, accept the same three kinds of input:

  • Clearnet URL — paste example.com or a full https:// URL and press Enter.
  • .onion address — paste the whole 56-character name; Tor resolves it directly. Every .onion row in the directory also has a copy button.
  • Search — plain words (separated by spaces) are sent to DuckDuckGo's .onion search service instead of being treated as a URL.

The same directory is published on this site at Links, together with a checker that tells you exactly how a given link will be opened.

File scanner

The site includes an on-device file scanner at Scan. It inspects any file entirely in your browser: it computes the SHA-256 and SHA-1 hashes, identifies the true file type from its magic bytes and flags mismatches with the extension, lists executables and scripts hidden inside ZIP archives, and reports suspicious content patterns such as encoded PowerShell, download-and-run commands and Office macros. The file is read locally and never uploaded.

Because the published SHA-256 values of the release installers are embedded in the scanner, dragging in a downloaded TorSecretBrowser-* file will confirm whether it is byte-for-byte the file we published. The scanner is a heuristic and integrity tool, not a malware-database antivirus, so a clean result is not a guarantee of safety.

How privacy works

ConcernImplementation
Tor processThe app generates a torrc, spawns the real tor daemon, waits for the control port, authenticates with cookie auth and reports bootstrap progress.
All traffic through TorEvery tab session is forced to socks5://127.0.0.1:<port> with proxyBypassRules: '<-loopback>'. Chromium's SOCKS5 uses remote DNS, so hostnames are resolved by Tor.
.onion resolutionWorks for free — onion names are resolved by Tor over the same SOCKS5 channel.
No DNS leakChromium never resolves names itself, and the generated torrc sets SafeSocks 1, which makes Tor refuse any locally-resolved request.
No WebRTC leakRuns with --force-webrtc-ip-handling-policy=disable_non_proxied_udp; the page's RTCPeerConnection and mediaDevices are removed. Tor carries no UDP.
No protocol escapews:/wss: go through the proxy; every other scheme (e.g. ftp:, custom app URIs) is cancelled by a webRequest filter.
Circuit isolationEach tab gets its own in-memory partition and its own local SOCKS5 relay that injects unique credentials. With Tor's IsolateSOCKSAuth, distinct credentials mean distinct circuits.
Privacy by defaultNo telemetry, no persistent profile: partitions are created without the persist: prefix, so cookies, cache and storage live only in memory.

Onion services

Onion v3 addresses (56-character <id>.onion names) are resolved by the Tor daemon itself. Paste one into the address bar and press Enter — there is no configuration, extension or "onion mode" to enable.

New Identity

Choosing New Identity:

  • sends SIGNAL NEWNYM to Tor so future streams use fresh circuits;
  • rotates every tab's SOCKS credentials;
  • drops all per-tab cookies, cache and storage.

Because every circuit is torn down, expect a few seconds of re-bootstrapping before browsing feels fast again.

Configuration

The app locates a Tor binary in this order:

  1. the TOR_BINARY environment variable,
  2. the bundled binary at resources/tor/<platform>-<arch>/tor[.exe],
  3. tor / tor.exe on your PATH.

Tor's state lives in <app user data>/tor-data/ — this contains the generated torrc, the control auth cookie and Tor's guard state. Delete the folder at any time to reset your guards.

OSLocation of tor-data
Windows%APPDATA%\Tor Secret Browser\tor-data
macOS~/Library/Application Support/Tor Secret Browser/tor-data

Build from source

Requires Node.js 18+ and npm. The download script needs tar (present on Windows 10+, macOS and Linux).

# clone the repository
git clone https://github.com/itriedcoding/TorSecretBrowser.git
cd TorSecretBrowser

# install Electron and build tooling
npm install

# download the official Tor Expert Bundle for your platform
npm run fetch-tor

# launch
npm start

Package an installer

npm run dist      # installer for the current OS (NSIS / DMG / AppImage)
npm run dist:dir  # unpacked build for quick testing

Verify the build

Three checks ship with the source, and none of them are placeholders:

npm run syntax-check   # static parse of every source file
npm run smoke          # Electron integration test; no network needed
npm run test:tor       # launches real Tor, waits for bootstrap, then NEWNYM

npm run smoke stands up a fake Tor SOCKS5 endpoint and asserts that the browser reaches it through the per-tab shim, that different tabs use different isolation usernames, that .onion CONNECT requests are relayed, and that WebRTC is removed from the page. npm run test:tor proves the real daemon starts, authenticates over the control port and builds circuits.

Troubleshooting

"Tor binary not found"

Install Tor, set TOR_BINARY, or run npm run fetch-tor. On Debian/Ubuntu: sudo apt install tor. On macOS: brew install tor.

Stuck at "Starting Tor…" / never reaches 100%

Your network is likely blocking Tor (it uses OR ports such as 443 and 9001).

  • Allow Tor through your firewall or proxy.
  • Use bridges: add bridge lines to the torrc at <userData>/tor-data/torrc after the first run. obfs4 bridges ship inside the Expert Bundle under pluggable_transports/.

A specific site doesn't load

Many sites block Tor exits or have no onion version. Errors appear in the diagnostic log — click the Tor chip to expand it.

Performance

Traffic takes three relays around the world and is encrypted at each hop, so latency is higher than a normal browser. This is inherent to Tor, not to this app. Upload-heavy pages are the slowest.

Multiple instances

Only one instance runs at a time (a single-instance lock), so two Tor daemons or control connections never race.

Limitations

These are real and stated up front:

  1. Fingerprint resistance is partial. This build reuses Chromium via Electron. Its fingerprinting surface (fonts, canvas, WebGL, audio, screen metrics, TLS/HTTP stack) differs from Firefox/Gecko, and Tor Browser's letterboxing and first-party isolation are not reproduced. For the strongest anonymity guarantees, use the official Tor Browser.
  2. Circuit isolation is per tab, not per site. Tabs are isolated from each other; there is no Firefox-style first-party isolation inside a single tab.
  3. WebRTC is disabled, not proxied. Sites that require WebRTC media will not work. This is deliberate.
  4. No extensions, password manager or sync. Anything that could punch a hole through the proxy is intentionally absent.
  5. The "no history" model is in-memory per session. It does not defend against an attacker with access to your machine or swap; use full-disk encryption.
  6. OS-level leaks are out of scope. If your OS or another app leaks traffic, this browser cannot stop that. Consider a VM or Tails for high-risk use.

FAQ

Is this the Tor Browser?

No. It is a from-scratch Chromium (Electron) shell that uses Tor. It is not a reskinned Tor Browser and does not reproduce all of its anti-fingerprinting features.

Does it cost anything?

No. It is free and open source under the MIT license.

Does it work without internet censorship circumvention?

Yes — on an open network it connects directly. On restricted networks, configure bridges as described above.

Where is the source?

On GitHub: itriedcoding/TorSecretBrowser.
